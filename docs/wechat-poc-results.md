验证日期：2026-10-03。独立本地工作树 `codex/podcast-free-poc`，复用播客 POC 的本地模型和阅读服务。没有修改生产应用、部署线上或启用后台定时；尚未提交/推送本轮 POC。

## 可体验内容

运行 `research/podcast_poc/poc.py serve --port 8767` 后，打开 <http://127.0.0.1:8767/wechat>。顶部可切换播客，公众号支持财经/AI/技术分类、标题及已获取正文搜索、原文链接、来源状态、正文文字阅读、展开摘要引用段落。页面刷新只读取本地结果；抓取和摘要由 CLI 显式执行，命令见 [README](../research/podcast_poc/README.md)。

六源 live public RSS 拉取均成功，每源选发布时间最新的两篇，共12篇具备 `content:encoded` 正文。正文是否存在与微信原文是否完整是两项不同判断；本次没有逐段对照微信原页，也没有解析图片或图表。最新文章日期为9月22–28日，采集日为10月3日；没有真实阅读量/点赞量或热度排名。

## 成本与运行结果

- 已复用本机 `mlx-community/Qwen3-4B-Instruct-2507-4bit`，模型准备后强制离线推理；0次付费API调用、无需公众号登录或云端推理密钥。使用现有Mac的算力、存储和网络，并不意味着物理资源无成本。
- 6篇成功完成，全部处理所取得的文字段落。美团长文分2块，其余每篇1块。处理用时分别为16.26、14.07、14.11、27.91、52.68、66.99秒，总计192.02秒；包含模型加载和摘要处理，不能当作纯模型吞吐量指标。
- 三篇抽查都发现语义问题。猫笔刀初稿把个人考虑区间写成走势预测、提案写成已实施禁购；量子位初稿扩大受访企业统计范围、将客户案例写成已验证普遍效果；腾讯初稿遗漏同批50条案例用于调优/回归的限制，并错误合并置信度评分项。
- 当前三篇展示修订稿来自本轮助手对照RSS文字复核，`model_draft_summary`保留原草稿，页面可展开对比。其余三篇仍为明显标注的模型初稿。复核不是本地自动流程，也未独立核查文章主张、原微信页面、图表或经营数据。

结论：**免费采集→正文阅读→本机中文摘要→段落出处链路已跑通；自动摘要质量未达到无人值守可信要求。** 不能将修订稿表现当作4B本地模型的自动质量。

## 数据与失败边界

- 元信息/description与`content:encoded`分开处理，缺少正文、少于200个非空白字符或命中验证页标记时不生成全文摘要；200字只是可读性门槛，不验证无删节。
- 去除HTML活动内容，不加载第三方图片；表格单元格保留分隔避免数字拼接，逐段保留文字。引用只做结构合法性校验，ID存在不代表语义被支持。
- 按实际发布时间排序，不把抓取时间当成发布时间；按微信URL稳定字段去重。正文或标题变更清除旧摘要和复核，源失败保留已存文章并记录失败状态。
- 原始RSS、正文、摘要、复核、模型和QA截图保存在忽略目录 `private/podcast-poc` / `.podcast-models`，不写入版本库。可重复运行的代码和来源配置可审阅。
- 仅监听本机回环地址，网页是只读API；没有线上鉴权/多用户/长期留存/无人值守队列能力。接入线上KOL前仍需产品与运行边界设计。

## 验证证据

- 20项离线测试通过（原播客10项 + 新公众号10项），覆盖简介边界、表格数值、嵌套HTML、链接去重、内容变化失效、乱序RSS、失败保留、日期真实性及播客/公众号数据隔离。
- 真实本地API + Chrome桌面/390px手机验收通过：6来源/12正文/6摘要/3复核、3种分类、标题搜索、出处展开、微信原文链接、来源状态、播客导航和两个已有复核样本回归。无JS错误或水平溢出；阅读页没有第三方网络请求。
- 补充的浏览器临时数据验证通过：只有简介时即使错误传来summary也不展示全文摘要，危险URL不生成外链，HTML以纯文本显示。临时数据未写入业务记录。
- 最终机器可读摘要见 [wechat-poc-evidence.json](wechat-poc-evidence.json)；详细本机证据见忽略目录 `private/podcast-poc/qa/wechat-browser-evidence.json` 与桌面/手机截图。
